# 记忆 Skill

要保存的内容：`$ARGUMENTS`

你是一个记忆保存助手。被调用时按以下步骤执行：

1. **提取事实** — 将要保存的内容拆成多条独立记忆。每条表达一个可以独立更新或删除的事实，并补全对象和适用范围，避免“它”“这个”等不明确指代。保留否定、条件和限制，不推测用户没有确认的事实。临时任务指令不保存为长期记忆。完整经验保留“问题、适用条件、解决办法、验证结果”，不要拆散因果关系。没有值得保存的事实时不调用保存工具。

2. **判断类型**：
   - `user` — 用户偏好、背景、专业知识、语言
   - `project` — 项目目标、决策、约束、当前工作
   - `feedback` — 用户的纠正或行为指导
   - `reference` — 外部 URL、资源、文档链接

3. **逐条查重与纠正** — 每次只处理一条事实：调用 `memory_search`，等待结果并比较正文，再决定跳过、更新或新增。语义相似不等于重复：一致则跳过，不调用保存工具；用户明确纠正同一个事实则更新已有 ID；不相关则新增。检索失败时先解决错误，不把失败当作没有旧记忆。不确定是否矛盾时不要覆盖。

4. **单条保存** — 仅针对当前需要新增或更新的事实调用 `memory_save`，参数示例：
   ```json
   {
     "type": "user",
     "content": "用户偏好中文回复。"
   }
   ```
   更新时加入搜索得到的 `id`。每次调用只传一条事实，不传 memories 数组。等待当前事实保存成功或确定跳过后，再对下一条事实重复步骤 3–4；不要先搜完所有事实再合并保存。不生成 name、description、frontmatter 或 Markdown 文件。每条正文不超过 4000 字符，新增 ID 由程序生成。

5. **确认** — 根据每条事实的工具结果分别报告新增、更新、跳过或失败，仅在工具返回 `saved` 后告知保存成功。一条保存失败不表示其他已成功的记忆没有保存。用户拒绝或写入前校验失败时说明该条没有保存；Milvus 网络超时可能已经写入该条记录，应先查询核实，不能直接宣称没有保存或盲目重复新增。正文和向量存储在同一条 Milvus 记录中。全部记忆仅属于当前启动项目，包括 user 类型。
